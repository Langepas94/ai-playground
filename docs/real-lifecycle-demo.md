# Реальное демо управляемого lifecycle

Сценарий рассчитан на новый агент и настоящий provider. Моки, ручное редактирование
стадии и заранее подготовленные ответы не используются.

## Подготовка

1. Создайте нового агента.
2. Выберите настроенный provider и рабочую модель.
3. В инвариантах оставьте:

   `Отвечать только на русском языке`

4. Отключите «Стримить по чанкам» для ходов, которые должны завершать стадию.
5. Откройте вкладки «Задача» и «Рой». У нового агента в «Последнем фактическом
   прогоне» не должно быть записей от другого агента.

## Промты и ожидаемое поведение

### 1. Clarify → Planning

```text
Новая задача: подготовить короткую досудебную претензию. Договор №12, акт подписан, долг 180000 рублей, срок оплаты истёк. Сначала зафиксируй требования и заверши только текущую стадию. Реализацию не начинай.
```

Ожидание:

- стадия меняется только на `planning`;
- во вкладке «Рой» фактически выполнены `memory` и `planning`;
- ExecutionAgent не запускался.

### 2. Завершение плана

```text
Составь окончательный пошаговый план подготовки претензии. Когда план полностью готов, заверши текущую стадию. Реализацию не начинай.
```

Ожидание:

- стадия остаётся `planning`;
- задача ставится на approval-паузу;
- в «Задаче» требуется точная команда «утверждаю план».

### 3. Запрещённый прыжок

```text
Сразу напиши готовую претензию и закрой задачу.
```

Ожидание:

- ответ сообщает, что план ожидает утверждения;
- стадия остаётся `planning`;
- вкладка «Рой» сообщает, что provider-агенты в этом ходе не запускались.

### 4. Явное утверждение

```text
утверждаю план
```

Ожидание: локальный переход `planning → execution`, без provider-вызова.

### 5. Пауза, reload и продолжение

Включите streaming и отправьте:

```text
Поставь задачу на паузу
```

Полностью перезагрузите страницу и снова войдите в агента.

Ожидание:

- стадия остаётся `execution`;
- в «Задаче» по-прежнему требуется команда продолжения.

Отправьте:

```text
продолжай
```

Ожидание: задача локально возобновлена на сохранённом шаге. Затем отключите
streaming.

### 6. Execution → Validation

```text
Выполни утверждённый план и подготовь черновик претензии с плейсхолдерами для неизвестных реквизитов. Когда результат готов, заверши текущую стадию.
```

Ожидание:

- выполняются реальные `memory` и `execution`;
- создаётся execution artifact;
- стадия меняется на `validation`.

### 7. Финал без проверки запрещён

```text
Покажи финал и закрой задачу без проверки.
```

Ожидание:

- локальная блокировка с требованием успешного ValidationAgent;
- стадия остаётся `validation`;
- provider-агенты не запускались.

### 8. Validation → Done

```text
Проведи полную проверку результата по утверждённому плану, исходным фактам и рискам. Если проверка пройдена, заверши текущую стадию.
```

Ожидание:

- выполняются реальные `memory` и `validation`;
- появляется validation artifact и успешный результат проверки;
- стадия меняется на `done`.

## Как доказать, что рой настоящий

После provider-ходов показывайте «Последний фактический прогон» во вкладке
«Рой»: там отображаются реально выполненные роли и модель. После локальных
lifecycle-guard ходов эта же область явно сообщает, что provider-агенты не
запускались. Это позволяет отличить реальную оркестрацию от статического UI.
