# Web UI

Локальный web UI запускается той же командой, что и раньше:

```bash
ai web
```

По умолчанию интерфейс доступен на `http://127.0.0.1:8787`.

## Основной экран

Web UI по-прежнему построен вокруг большого диалога слева и inspector справа, но текущая версия заметно богаче скриншотов из `docs/assets/`.

- Слева: история, поле `Новый запрос`, кнопка вложений `📎`, `Отправить`, `Стоп`, `Новая сессия` и переключатель `Стримить по чанкам`.
- Справа: вкладки `Профиль`, `Параметры`, `Метрики`, `Debug`.

PNG-скриншоты в `docs/assets/web-chat-inspector-*.png` показывают ранний layout 1.0 и сейчас служат только исторической иллюстрацией. Они не отражают новые controls вроде стрим-тоггла, вложений, memory strategies и отдельного блока `Контекст` в метриках.

## Как пользоваться

1. Откройте `ai web`.
2. Во вкладке `Профиль` выберите `agent`, provider и model.
3. При необходимости загрузите live model list кнопкой `Загрузить модели` и проверьте badge `Контекст`.
4. Если токен еще не сохранен, вставьте его в `API token override` и нажмите `Сохранить токен`.
5. При необходимости укажите `Base URL` или `Custom model id`.
6. Прикрепите текстовые файлы через `📎`, если они должны уйти в prompt.
7. Введите запрос в поле `Новый запрос`.
8. Выберите режим доставки: стримить по чанкам или ждать полный ответ целиком.
9. Нажмите `Отправить`.

Кнопка `Новая сессия` начинает отдельный локальный диалог. Кнопка `Стоп` отменяет активный HTTP-запрос. История, memory state и накопленные metrics хранятся локально; токены в историю не пишутся.

Поля `max_tokens` и `max_completion_tokens` пустые по умолчанию. Пустое поле означает, что лимит не будет отправлен provider API. Чтобы ограничить ответ, введите число вручную во вкладке `Параметры`.

`System prompt` сохраняется как первое системное сообщение агентной сессии. При возврате в сохраненную сессию Web UI восстанавливает его во вкладке `Параметры`, чтобы агент продолжал работу с той же ролью и инструкциями.

## Inspector

- `Профиль` - agent mode, provider, model, context badge, live model list, token status, base URL и custom model id.
- `Параметры` - `system_prompt`, memory strategy, pricing, Billing API, response controls, reasoning/verbosity и extra API parameters.
- `Метрики` - статистика последнего запроса, контекстных вспомогательных вызовов и накопленная статистика текущего диалога.
- `Debug` - ссылка на документацию провайдера, raw provider request/response и debug по context topics/facts.

## Контекст и память

Во вкладке `Параметры -> Контекст` можно выбрать strategy:

- `Summary` - хранит summary и последние N raw сообщений; умеет preflight-сжатие при приближении к context window.
- `Sliding Window` - отправляет только последние N raw сообщений без суммаризации.
- `Sticky Facts` - после сообщений пользователя обновляет локальные KV-факты и показывает их preview/debug.
- `Branching` - позволяет сделать checkpoint и вести две явные ветки `A/B`.
- `Scoped Branches` - автоматически или вручную маршрутизирует сообщения по темам внутри одной session.

UI показывает только релевантные controls выбранной strategy. Например, `Facts extraction prompt` виден только для `Sticky Facts`, а `Checkpoint + 2 ветки` только для `Branching`.

## Метрики токенов

Вкладка `Метрики` намеренно разделяет два уровня:

- `Токены запроса` - только основной provider API вызов последнего ответа.
- `Контекст` - cost/usage/time служебного контекстного шага, если он был.
- `Токены диалога` - накопление по текущей local session.

Если provider возвращает подробности usage, UI показывает breakdown:

- `prompt`
- `completion`
- `prompt cached`
- `prompt uncached`
- `prompt audio`
- `visible output`
- `reasoning`
- `output audio`
- `accepted prediction`
- `rejected prediction`
- `total`

Если context strategy не делала отдельный вспомогательный запрос, блок `Контекст` показывает смысловую подпись вроде `summary не запускался`, `facts обновлены локально`, `checkpoint не создан` или `последние N сообщ.`.

## Токены и хранение

Web UI использует тот же secret слой, что CLI:

- сначала системный keychain;
- затем локальный fallback `secrets.toon`, если keychain недоступен или не отдает сохраненное значение.

Fallback-файл лежит в локальной data-директории приложения и на Unix создается с правами `0600`. Токены не пишутся в `config.toml`, history, memory или debug output.

## TOON

Локальные session data и metrics сохраняются в TOON там, где формат поддерживает нужные структуры. Старый JSON-файл session metrics читается как legacy fallback, но новые metrics пишутся в `.metrics.toon`.
